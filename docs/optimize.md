# 工程优化清单

本文档用于记录 Brain Rush 的工程优化现状、已完成项、待实现项和可选增强项。它不是产品 PRD，也不是完整技术方案；产品需求见 [PRD.md](PRD.md)，当前架构见 [方案设计文档.md](方案设计文档.md)，RAG 当前实现见 [RAG当前实现说明.md](RAG当前实现说明.md)。

## 使用约定

- `所属端`：`前端`、`后端`、`前后端协同`、`数据/RAG`、`文档`。
- `状态`：`已完成`、`待实现`、`可选增强`。
- 每次完成一项优化后，更新对应条目的状态和说明。
- 只把已经落地的能力标为已完成；规划中的能力保持待实现或可选增强。

## 已完成优化

### 1. 后端重算分数与错题

- 所属端：后端
- 状态：已完成
- 说明：后端不信任前端传入的正确性字段，统一根据题目答案和用户选择重算正确率、分数和错题明细。
- 价值：避免前端传错值或被篡改后导致报告分数失真，是结果可信度的基础。

### 2. AI Client 缓存

- 所属端：后端
- 状态：已完成
- 说明：`LangChainAiClient` 改为进程内缓存，避免每次请求重复初始化模型客户端。
- 价值：减少重复构造开销，也方便统一挂 timeout、retry、日志等配置。

### 3. timeout / retry / 错误分类

- 所属端：后端
- 状态：已完成
- 说明：模型调用增加超时、重试和错误码分类，响应体包含 `code + detail`。
- 价值：用户侧错误提示更可读，排障时也能快速判断是鉴权、限流、超时还是上游异常。

### 4. 结构化输出 + fallback

- 所属端：后端
- 状态：已完成
- 说明：优先使用 structured output 获取题目和报告；如果结构化解析失败，再回退到同一次响应中的 raw JSON 解析。
- 价值：提升 AI 输出稳定性，同时兼容 OpenAI-compatible JSON mode 偶发不稳定。

### 5. Prompt 拆分与版本字段

- 所属端：后端
- 状态：已完成
- 说明：题目生成和报告生成 prompt 已从 `llm.py` 拆到 prompt 模块，并在响应/历史记录中保留 prompt version 和模型名。
- 价值：后续调 prompt、做多模型对比或定位历史输出问题时，有基础版本信息可追溯。

### 6. 请求日志 / Trace ID / 耗时监控

- 所属端：后端
- 状态：已完成
- 说明：后端增加结构化 JSON 日志和 `X-Request-ID` 响应头；HTTP 请求和 AI 调用记录关键耗时与错误信息。
- 价值：线上定位问题更快，也方便后续接入监控系统。

### 7. 前端消费后端错误码

- 所属端：前后端协同
- 状态：已完成
- 说明：前端保留后端返回的 `code + detail`，并根据错误码展示差异化提示。
- 价值：用户不只看到通用失败文案，排障和体验都更清晰。

### 8. 学习记录持久化

- 所属端：前后端协同
- 状态：已完成
- 说明：接入 PostgreSQL、微信静默身份、JWT 会话、历史保存、历史列表和历史详情。
- 价值：项目从一次性 demo 进入可沉淀学习记录的 MVP 形态。

### 9. API 入口限流与保护

- 所属端：后端
- 状态：已完成
- 说明：`/api/generate-quiz` 和 `/api/generate-report` 增加进程内固定窗口限流，默认按 IP + 接口每小时 10 次。
- 价值：保护模型额度，避免误操作或恶意请求刷空上游配额。

### 10. 前端会话结构收敛

- 所属端：前端
- 状态：已完成
- 说明：答题页状态抽到 `useQuizSession`，分数、正确率、首个未答题索引等计算抽到工具函数。
- 价值：减少重复状态和页面内复杂逻辑，降低后续迭代风险。

### 11. 前端视觉体系和基础壳组件

- 所属端：前端
- 状态：已完成
- 说明：全局视觉 token 和基础展示组件已收敛，首页、答题页、报告页完成视觉体系优化。
- 价值：小程序从“可跑 MVP”更接近可展示作品，后续改视觉成本更低。

### 12. 题目质量反馈与错题本复训

- 所属端：前后端协同
- 状态：已完成
- 说明：新增题目反馈表和 `/api/question-feedback`；新增 `/api/wrong-questions` 和错题本页，可从历史记录聚合错题并创建本地复训会话。
- 价值：反馈数据可反哺 prompt 和题库质量，错题复训让历史记录进入学习闭环。

### 13. Alembic 数据库迁移体系

- 所属端：后端
- 状态：已完成
- 说明：引入 Alembic 管理 PostgreSQL schema，初始化脚本切换为 `alembic upgrade head`，旧库可通过 `stamp-db.ps1` 标记版本。
- 价值：新增表、字段、索引有可追踪迁移记录，降低 schema 漂移风险。

### 14. UUID 主键与学习记录结构优化

- 所属端：后端
- 状态：已完成
- 说明：适合长期保存的业务表主键已统一迁移到 PostgreSQL UUID；`learning_records` 保留 `accuracy_percent`，去掉冗余 score 概念。
- 价值：主键类型更贴近 PostgreSQL 生产使用方式，学习记录字段含义更清晰。

### 15. pgvector RAG 支持

- 所属端：数据/RAG
- 状态：已完成
- 说明：启用 `pgvector`，给 `knowledge_chunks` 和 `question_bank_items` 增加 embedding、模型、版本、hash 和时间字段，并建立向量索引。
- 价值：知识片段和精选题可以被语义检索召回，不再只依赖关键词或纯 AI 出题。

### 16. Embedding 导入与内容 hash 跳过

- 所属端：数据/RAG
- 状态：已完成
- 说明：curated JSON 导入时会为 chunk/question 生成 embedding；内容、模型和版本未变化时跳过重复 embedding。
- 价值：避免重复消耗 embedding 额度，保证知识库数据和向量元数据一致。

### 17. hybrid RAG 检索链路基础版

- 所属端：数据/RAG
- 状态：已完成
- 说明：生成题目时先执行关键词检索 + 向量检索，并用 RRF 融合排序；精选题优先返回，不足时把检索上下文交给 AI 补题。当前版本已演进到 `hybrid-rag-v1.4`。
- 价值：降低纯 AI 出题的不稳定性，让自维护题库和知识库真正参与出题。

### 18. RAG 检索可观测性

- 所属端：数据/RAG
- 状态：已完成
- 说明：新增 `debug-rag.ps1`，可查看一次 query 命中的 questions/chunks、关键词分、关键词字段分数拆解、向量分、RRF 融合分、rank 和 `retrievalVersion`；前端开发环境展示题目来源。
- 价值：RAG 不再是黑盒，可以直接判断是否命中、命中了什么、排序是否合理。

### 19. `knowledge_documents` 资料来源模型与基础导入

- 所属端：数据/RAG
- 状态：已完成
- 说明：新增 `knowledge_documents` 表，预留 PDF、网页、Word、截图等具体资料来源；curated JSON 支持 document 层级，`knowledge_chunks` 可通过 `document_id` 关联来源。
- 价值：为后续资料导入 Pipeline 打基础，让每个 chunk 能追踪具体资料来源，同时保持旧 JSON 格式兼容。

### 20. 文档入口与 RAG 文档拆分

- 所属端：文档
- 状态：已完成
- 说明：根 README 调整为项目入口，新增 docs 导航，RAG 文档拆成当前实现和后续优化两类。
- 价值：文档主叙事从早期 MVP 规划升级为当前真实能力 + 后续路线。

### 21. 关键词检索升级到 PostgreSQL FTS 和 v1.4 调优

- 所属端：数据/RAG
- 状态：已完成
- 说明：当前 `hybrid-rag-v1.4` 优先使用 PostgreSQL Full-Text Search；本机可通过 `install-pg-jieba.ps1` 尝试安装 `pg_jieba` 并启用 `jiebacfg` 中文分词，不可用时降级到 `simple` FTS 和 Python 字段加权 scorer。v1.4 还补充中文领域短语、收窄同义词扩展并降低泛词权重。
- 价值：提升标题、tags、正文和专有术语命中的可控性，同时通过 `keywordScoreBreakdown` 让关键词排序更可调试。

### 22. 本地文件资料导入 Pipeline 最小版

- 所属端：数据/RAG
- 状态：已完成
- 说明：新增本地 `.txt`、`.md` 和文本型 `.pdf` 导入 Pipeline，自动提取文本、清洗、切 chunk，并复用 curated 导入流程写入 document/chunks 和 embedding 元数据。
- 价值：知识库维护不再只能手写 JSON，后续可在同一结构上扩展 URL、Word、OCR 和异步任务。

### 23. 知识库后端管理 API

- 所属端：数据/RAG
- 状态：已完成
- 说明：新增 `/api/admin/rag/*` 管理接口，通过 `ADMIN_API_TOKEN` 和 `X-Admin-Token` 保护，支持 collection/document/chunk/question 查看、筛选、启停、轻量编辑和手动重跑 embedding。
- 价值：知识库条目不再只能通过改 JSON 管理，便于排查、停用错误资料和修正 chunk/source/tags。

### 24. 独立 admin-web 知识库工作台

- 所属端：前后端协同
- 状态：已完成
- 说明：新增独立 `admin-web`，支持 collection/document/chunk/question 列表、筛选、详情查看、轻量编辑、启停、手动 reembed、Debug 和 Imports 页面；页面文案已中文化并做了简洁化调整。
- 价值：知识库维护从接口和脚本操作升级为可视化工作台，便于日常排查和轻量运营。

### 25. RAG 导入任务队列与可观测性

- 所属端：数据/RAG
- 状态：已完成
- 说明：Imports 上传 `.txt`、`.md` 和文本型 `.pdf` 后会创建 `rag_import_jobs`，通过 Redis + RQ worker 异步执行；后台展示 Redis、队列 waiting job、worker、stale queued/running、导入统计和失败原因，并支持 Requeue。
- 价值：导入任务不再依赖用户看命令行猜状态，worker 未启动、Redis 异常、任务长时间未处理都能在页面上直接发现。

### 26. RAG 评估集与分类统计

- 所属端：数据/RAG
- 状态：已完成
- 说明：`backend/data/rag-eval.json` 已扩展为带 `category` 的评估集，eval 输出保留全局 top1/top3/top5/failures，同时增加 `byCategory` 和 `categoryOrder`，失败项包含分类和实际命中。
- 价值：检索调优不再只看总命中率，可以定位 chunking、embedding、hybrid retrieval、evaluation、reliability 等分类里的弱项。

### 27. RAG 数据一致性检查

- 所属端：数据/RAG
- 状态：已完成
- 说明：新增 `check-rag-data.ps1`，对比 `backend/data/rag-knowledge.json` 与数据库中的 active collection/document/chunk/question，输出缺失、停用和 document 标题不一致条目。
- 价值：eval 低分时可以先确认本地知识库是否同步，避免把数据未导入误判成检索算法问题。

### 28. hybrid-rag-v1.4 检索质量调优

- 所属端：数据/RAG
- 状态：已完成
- 说明：检索版本升级到 `hybrid-rag-v1.4`，补充中文领域短语识别、拆分过宽同义词、降低 `RAG`/疑问词等泛词权重，并继续保留 keywordScoreBreakdown、keywordRank、vectorRank 和 RRF 诊断字段。
- 价值：在不引入 Rerank 的前提下，显著提升当前评估集 top5 命中率，并让剩余问题更容易定位。

## 待实现优化

### 1. 产品数据埋点 V1

- 所属端：前后端协同
- 状态：待实现
- 说明：记录首页访问、输入提交、生成开始/成功/失败、开始答题、每题作答、完成闯关、查看复盘、点击历史/错题/分享等关键事件。
- 价值：让下一阶段优化从“凭感觉判断”转为基于真实转化和失败数据判断。

### 2. 分享闭环 V1

- 所属端：前端
- 状态：待实现
- 说明：复盘页支持微信分享，分享内容包含学习主题和结果摘要；好友打开后进入同主题学习入口，并记录分享点击和打开事件。
- 价值：验证小程序传播价值，同时避免暴露分享者完整答题详情。

### 3. 内容安全与失败兜底

- 所属端：前后端协同
- 状态：待实现
- 说明：补充输入侧基础内容安全、AI 输出异常提示、生成失败重试和报告失败时的本地模板兜底。
- 价值：让普通用户试用时不容易因为模型异常、违规输入或报告失败而卡死。

### 4. 资料处理 Pipeline 扩展

- 所属端：数据/RAG
- 状态：待实现
- 说明：在本地文件最小版和 Imports 队列基础上，继续支持 URL、Word、截图 OCR、自动 tags、批量上传、取消任务、更细阶段进度和导入审核。
- 价值：知识库建设从本地脚本升级到可维护、可追踪的资料导入系统。

### 5. 检索评估历史与门禁

- 所属端：数据/RAG
- 状态：待实现
- 说明：在现有 eval 分类统计基础上，保存历史评估结果、对比不同检索版本，并考虑在 CI 中增加最低命中率门禁。
- 价值：让检索质量变化可追踪，避免后续调参无意中拉低已覆盖主题的命中率。

### 6. 关键词检索继续校准

- 所属端：数据/RAG
- 状态：可选增强
- 说明：当前已升级到 `hybrid-rag-v1.4`；后续可继续用评估集校准字段权重、中文同义词、RRF 参数，或在数据规模扩大后评估 BM25。
- 价值：提升专有名词、数字、英文缩写和精确概念的召回稳定性。

### 7. 混合排序策略继续校准

- 所属端：数据/RAG
- 状态：已完成基础版
- 说明：当前已使用 RRF 融合关键词结果和向量结果；后续可结合评估集继续校准 RRF 参数、字段权重和分数归一化方案。
- 价值：降低不同检索器分数尺度不一致造成的排序偏差。

### 8. 知识库后台审核流和编辑增强

- 所属端：前后端协同
- 状态：待实现
- 说明：基于现有 admin-web，继续补完整题目结构编辑、新增/删除、批量操作、导入审核、取消任务、版本回滚和更细进度展示。
- 价值：知识库规模扩大后，让维护从接口调试升级为可视化后台。

## 可选增强

### 1. Rerank 精排

- 所属端：数据/RAG
- 状态：可选增强
- 说明：当知识库达到几千 chunk，或 top 20 已命中但 top 5 排序不准时，再升级到 `hybrid-rag-v2`。
- 价值：在候选召回已有基础上提升最终上下文排序质量。

### 2. query embedding 缓存

- 所属端：数据/RAG
- 状态：可选增强
- 说明：对常见 query 或相同 query 的 embedding 结果做短期缓存。
- 价值：降低重复 embedding 成本。

### 3. AI 生成题审核入库

- 所属端：前后端协同
- 状态：可选增强
- 说明：AI 运行时生成题先暂存，结合用户反馈和答题表现，经审核后进入 `question_bank_items`。
- 价值：逐步沉淀高质量题库，同时避免低质量生成污染精选题。

### 4. 历史搜索、筛选和学习画像

- 所属端：前后端协同
- 状态：可选增强
- 说明：基于历史记录、错题和反馈构建更丰富的学习回看与画像能力。
- 价值：提升长期留存和复训价值。
