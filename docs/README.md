# 文档导航

本文档是 `docs` 目录入口，用于说明每份文档的职责、阅读顺序和维护规则。当前项目已经从早期 MVP 规划进入可持续迭代阶段，文档应优先反映当前真实实现，再补充后续路线。

## 推荐阅读顺序

1. [根 README](../README.md)
   - 项目入口，说明当前能力、技术栈、本地启动、测试命令和文档导航。
2. [PRD.md](PRD.md)
   - 产品视角，说明目标用户、核心场景、功能需求和优先级。
3. [方案设计文档.md](方案设计文档.md)
   - 技术视角，说明当前架构、核心业务流程、API、数据结构和后续路线。
4. [RAG当前实现说明.md](RAG当前实现说明.md)
   - RAG 当前实现细节，包括数据库表、导入、embedding、hybrid 检索和调试方式。
5. [RAG后续优化与扩展.md](RAG后续优化与扩展.md)
   - RAG 的已知粗糙点、优化方向和推荐推进顺序。
6. [optimize.md](optimize.md)
   - 工程优化清单，记录已完成、待实现和可选增强项。
7. [Learning.md](Learning.md)
   - 历史交接笔记，保留早期上下文；后续不作为主要项目文档入口。

## 文档职责

| 文档 | 主要职责 | 不应承担的内容 |
| --- | --- | --- |
| `README.md` | 项目入口、启动方式、常用命令、文档导航 | 大段技术设计、长篇需求细节 |
| `PRD.md` | 产品目标、用户场景、功能需求、优先级 | 具体代码结构、数据库迁移细节 |
| `方案设计文档.md` | 当前技术架构、接口设计、数据结构、系统路线 | 过期 MVP 执行流水账 |
| `RAG当前实现说明.md` | 当前 RAG 的真实实现和操作方式 | 远期知识库平台畅想 |
| `RAG后续优化与扩展.md` | RAG 后续优化、扩展点、成熟化路线 | 当前链路的重复教程 |
| `optimize.md` | 工程优化项和状态跟踪 | 产品故事、完整技术方案 |
| `Learning.md` | 历史上下文和早期交接记录 | 作为当前主文档或唯一事实来源 |

## 维护规则

- 先更新当前事实，再写后续规划；不要把未实现能力写成已完成。
- 如果一个能力已落地，应在 README 或方案文档中体现当前状态。
- 如果一个能力只是方向，应放在 PRD 的后续范围、方案文档的扩展路线或对应专题文档中。
- RAG 相关内容分工：
  - 当前实现写入 `RAG当前实现说明.md`。
  - 后续优化写入 `RAG后续优化与扩展.md`。
  - README 只保留入口链接和简短概览。
- `collection` 表示知识领域，不表示资料批次；`tags` 表示子主题；具体资料来源后续由 `knowledge_documents` 承载。
- 文档均使用 UTF-8 编码，更新时不要引入乱码或无意义的整文件格式化。
